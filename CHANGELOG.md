## [v1.7.0] - 2026-09-16

### Добавлено
- **Турбо-режим пакетного применения изменений (`--fast` / `--batch`)**:
  - Флаги `--fast` и `--batch` (синонимы) для команд `mlm sync`, `mlm append`, `mlm remove`.
  - Упаковка изменений в пакеты (по умолчанию по 250 записей, настраивается через `--batch-size`) и атомарное выполнение через RouterOS скрипты (`POST /rest/execute` с прозрачным fallback на `/rest/system/script`).
  - Увеличение скорости применения многотысячных списков в десятки раз (обработка списков в 8 000+ записей за секунды вместо десятков минут).
  - Защита от сбоев отдельных записей: каждая команда в скрипте оборачивается в `:do { ... } on-error={}`.
  - Автоматический fallback: при непредвиденной ошибке выполнения скрипта на роутере утилита плавно переключается на стандартный параллельный режим REST API.
- **Мгновенная очистка списков `mlm purge` через RouterOS скрипты**:
  - `mlm purge` теперь удаляет все записи списка одной RouterOS командой `/ip firewall address-list remove [find where list="..."]` за доли секунды (~0.1–0.2 с).
  - Сохранён автоматический fallback на параллельное удаление отдельных записей, если у пользователя API нет прав на выполнение скриптов.
- **Интеллектуальный перехват Ctrl+C (SIGINT) и предложение авто-отката (Rollback)**:
  - Корректная обработка сигнала прерывания во время `mlm sync`: вывод понятного предупреждения `⚠ Синхронизация списка прервана пользователем (Ctrl+C)` и завершение с кодом `130`.
  - Отключён избыточный вывод длинного блока `Usage` при возникновении ошибок или прерывании процесса (`SilenceUsage: true`).
  - Аккуратная очистка строки прогресс-бара при прерывании без артефактов в терминале.
  - Интерактивное предложение мгновенного отката к предварительно созданному автоматическому снимку: `Откатить изменения списка к снимку? [Y/n]`.
  - Если исходный список на роутере был пуст, откат выполняется мгновенно одной скриптовой командой очистки за 0.1 секунды.
  - Если откат отклонён пользователем, выводится готовая команда для ручного отката в любое удобное время (`mlm rollback -l <list> --id <snapID>`).

## [v1.6.1] - 2026-09-16

### Добавлено
- **Оффлайн-конвертер форматов `convert` (`internal/cli/convert.go`)**:
  - Новая команда `mlm convert [файл|URL|-]` для двусторонней оффлайн-конвертации между `native` (`.list`/`.lst`) и `mikrotik` (`.rsc`) без подключения к роутеру.
  - Автоматическое определение формата источника (`--format auto`) и выбор противоположного целевого формата.
  - Поддержка чтения из локальных файлов, прямых HTTP/HTTPS URL или стандартного ввода (`-`), чистый вывод в stdout для передачи в пайпы.
  - Флаг `--write / -w` для перезаписи исходного локального файла сконвертированным результатом на месте (in-place).
  - Поддержка локального DNS-резолвинга `--resolve-domains` и кастомного `--dns` перед конвертацией.
  - Полное сохранение отключённых записей (`!` $\leftrightarrow$ `disabled=yes`) и комментариев (`##` $\leftrightarrow$ `comment="..."`).
- **Безопасная полная очистка списков `purge` (`internal/cli/purge.go`)**:
  - Новая команда `mlm purge` для полного удаления всех записей из указанных списков (`-l / --list`) или со всех списков роутера (`--all`).
  - Автоматическое создание локального снимка (`snapshot.Save`) перед удалением для мгновенного отката через `mlm rollback`.
  - Защита от случайного сноса данных: интерактивный диалог подтверждения с указанием количества записей (`huh.NewConfirm`) и блокировка выполнения в неинтерактивных скриптах без флага `--force / -y`.
  - Поддержка безопасной симуляции `--dry-run / -n`, параллельного удаления (`--concurrency / -c`) и индикатора прогресса (`progressbar`).

## [v1.6.0] - 2026-09-16

### Добавлено
- **Единое имя команды и бинарник `mlm` (`cmd/mlm`)**:
  - Утилита полностью стандартизирована под лаконичное имя `mlm` (`cmd/mlm/main.go`).
  - Установка через Go пакетный менеджер одной командой: `go install github.com/D4n13l3k00/mikrotik-lists-manager/cmd/mlm@latest`.
  - Все команды, примеры, подсказки и автодополнение (`completion`) переведены на `mlm`.
  - Автоматическое определение версии через `runtime/debug.ReadBuildInfo()`.
  - Полная обратная совместимость с конфигами `.mikrotik-lists-manager.yaml` и старыми папками снимков.
- **Синхронизация напрямую по URL (`internal/source`)**:
  - Поддержка ссылок `http://` и `https://` во всех командах работы со списками (`sync`, `append`, `optimize`, `diff`, `validate`).
  - Автоматический заголовок User-Agent, валидация кодов ответа и таймауты.
  - Единая обработка локальных файлов, удалённых URL и стандартного ввода (`-`).
- **Локальный DNS-резолвинг доменов (`internal/dnsresolver`)**:
  - Флаг `--resolve-domains` для команд `sync`, `append` и `diff`.
  - Разрешение доменных имён в IPv4/IPv6 на клиенте с параллельным пулом воркеров.
  - Сохранение исходного домена в комментарии записи (`[resolved: domain.com]`).
  - Флаг `--dns` для указания кастомного DNS-сервера (например `1.1.1.1:53` или `8.8.8.8`).
- **Глубокая валидация и проверка списков (`validate` & `internal/validator`)**:
  - Новая команда `mlm validate <file|url>`.
  - Обнаружение синтаксических ошибок, неканонических CIDR (ненулевые биты хоста), дубликатов и поглощённых подсетей (shadowed subnets).
  - Сводная статистика (хосты, подсети, домены, выключенные).
  - Флаг `--strict` для CI/CD и pre-commit проверок (exit code 1) и вывод в `--json`.
- **Автономная команда `diff` (`diff`)**:
  - Новая команда `mlm diff <source1> [source2]`.
  - Оффлайн-режим: сравнение двух списков/URL без подключения к роутеру.
  - Сравнение источника со списком адресов на MikroTik (`mlm diff list.lst -l vpn`).
  - Наглядный цветной unified-diff (`+`, `−`, `~`) и поддержка `--json`.
- **Быстрый откат и система снимков (`internal/snapshot`, `snapshot` & `rollback`)**:
  - Автоматическое создание снимка перед применением изменений в `sync` (отключается флагом `--no-snapshot`).
  - Команды `mlm snapshot list`, `create`, `delete`.
  - Команда `mlm rollback -l <list>` для быстрого отката к последнему (`latest`) или указанному (`--id`) снимку.
  - Автоматическая ротация (хранение до 10 последних снимков) и защита от массового удаления (`--force / -y`).
- **Комплексная поддержка прокси (`internal/netutil`, `--proxy`, `MT_PROXY`)**:
  - Поддержка протоколов SOCKS5, SOCKS5h, HTTP CONNECT и HTTPS.
  - Туннелирование DNS-запросов через TCP (RFC 1035 / RFC 7766) через прокси для надёжной работы за фаерволами.
  - Прямое подключение к REST API MikroTik (без прокси).
  - Настройка через CLI-флаг `--proxy`, переменную окружения `MT_PROXY` или секцию `proxy:` в конфиге и профилях.

### Исправлено
- **HTTP CONNECT прокси буферизация**: Устранена потеря начальных байтов данных целевого сервера в `httpConnectDialer` из-за опережающего чтения `bufio.Reader` (внедрён `bufferedConn`).
- **Стабилизация сетевых тестов**: Устранены гонки сокетов и ложный `EOF` в `internal/netutil/proxy_test.go`.

## [v1.5.0] - 2026-09-14

### Добавлено
- **Профили роутеров (поддержка нескольких устройств)**:
  - Поддержка секции `profiles:` и `default_profile` в YAML-конфигурации.
  - Глобальный флаг `--profile / -P` и переменная окружения `MT_PROFILE`.
  - Приоритет параметров: CLI-флаг > переменная окружения > выбранный профиль > глобальный конфиг > дефолты.
  - Обновлена команда `config show` для вывода пути к конфигу, активного профиля и списка доступных профилей.
- **Глобальный автопоиск конфига**:
  - Автоматический поиск конфигурационного файла по цепочке:
    1. Явный путь через `--config`
    2. Текущая директория (`./.mlm.yaml`, `./.mikrotik-lists-manager.yaml`)
    3. Системная директория пользователя (`~/.config/mlm/config.yaml` на Linux/macOS, `%APPDATA%\mlm\config.yaml` на Windows)
    4. Домашний каталог пользователя (`~/.mlm.yaml`)
  - Флаг `config init --global / -g` для создания конфига в глобальной директории пользователя.
- **Машиночитаемый вывод в JSON (`--json`)**:
  - Флаг `--json` в команде `list` для структурированной сводки (`[]ListSummaryDTO`) или записей (`[]EntryDTO` с `-e`).
  - Флаг `--json` в команде `find` для вывода найденных записей с указанием типа (`exact` или `subnet`).
  - Флаг `--json` в команде `info` для вывода системной информации о роутере и RouterOS (`RouterInfoDTO`).
- **Вложенность подсетей и CIDR в `find`**:
  - Многонаправленный поиск подсетей на базе `net/netip`:
    - Искомый IP внутри подсети роутера (IP в CIDR)
    - Подсеть роутера внутри искомой подсети (CIDR в CIDR)
    - Искомая подсеть внутри подсети роутера
    - Точное совпадение с канонической нормализацией адресов
  - Точные совпадения подсвечиваются зелёным, совпадения по подсетям помечаются `(subnet)`.
- **Защита от массового удаления в `sync`**:
  - Защитный барьер при удалении > 50 записей или > 50% от текущего объёма списка.
  - Интерактивное подтверждение через `huh.NewConfirm` в терминале.
  - Флаг `--force / -y` для скриптов автоматизации и CI/CD.
  - В неинтерактивном окружении без `--force` выполнение прерывается с понятной ошибкой.
- **Параллелизм и оптимизация производительности**:
  - Последовательная синхронизация при указании нескольких списков (`-l list1,list2`), исключающая смешивание логов и баров прогресса при сохранении параллелизма запросов к API внутри каждого списка.
  - Параллельное выполнение `enable` и `disable` с флагом `--concurrency / -c` (по умолчанию: 5) и прогресс-баром при $\ge 10$ записях.
  - Параллельное переименование списка в `rename` с флагом `--concurrency / -c` и прогресс-баром.
  - Ограничение параллелизма в `fetch` через `--concurrency / -c` (по умолчанию: 6) с помощью `errgroup.SetLimit`.
  - Параллельные запросы нескольких ASN у провайдера RIPE STAT с потокобезопасной дедупликацией.
- **Сетевая надёжность и User-Agent**:
  - Механизм автоматических повторов (retries) на HTTP 429 Too Many Requests и ошибки 5xx в `fetcher` с экспоненциальной задержкой, джиттером и парсингом заголовка `Retry-After`.
  - Кастомный заголовок `User-Agent: mikrotik-lists-manager/<version> (+https://github.com/D4n13l3k00/mikrotik-lists-manager)` во всех HTTP-запросах к провайдерам и MikroTik REST API.
- **Натуральная сортировка IP/CIDR**:
  - Натуральная числовая сортировка по октетам в `list -e` (`compareAddresses`): `10.0.0.2` перед `10.0.0.10`, IPv4 перед IPv6, подсети по длине префикса.
- **CI/CD и тестирование**:
  - Матричный workflow `.github/workflows/ci.yml` для тестирования на Ubuntu, Windows и macOS (`go vet`, `go test -v -race`, сборка бинарников).
  - Модульные тесты для `internal/mikrotik`, `internal/config`, `internal/cli`, `internal/output`, `internal/parser`, `internal/syncer` и `internal/optimizer`.

### Исправлено
- **Разделение stdout и stderr**:
  - `export`: цветные заголовки перенаправлены в `stderr` при выводе в stdout для удобной работы с пайпами (`export > list.lst`).
  - `optimize`: логи и статистика перенаправлены в `stderr` при выводе в stdout (`optimize file.lst > out.lst`).
  - `optimize` корректно выводит исходный список в stdout, если изменений не потребовалось.
- **Сохранение состояния `disabled`**:
  - Экспорт сохраняет отключённые записи: префикс `!` в формате `native` и параметр `disabled=yes` в формате `mikrotik`.
  - Регулярное выражение парсера распознаёт `disabled=(yes|true)` из файлов экспорта RouterOS RSC.
- **Единая нормализация адресов**:
  - Исправлено прямое строковое сравнение в `append`, `remove` и `toggle`. Хосты нормализуются к `/32` (v4) или `/128` (v6), обнуляются биты хоста у подсетей.
- **Дедупликация в `syncer.Diff`**:
  - Устранена генерация дублирующихся изменений при наличии одинаковых адресов в файле (берутся атрибуты последней записи с выводом предупреждения).
